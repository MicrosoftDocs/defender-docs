# Agentic code security audit log reference (preview)

Agentic code security logs user and system actions to the Microsoft Purview unified audit log. Use these events to monitor activity, investigate incidents, and meet compliance requirements.

For information on how to search the audit log, see [Search the audit log in the Microsoft Purview portal](/purview/audit-new-search).

## Audited operations

The following operations are logged for agentic code security. All records use **Workload** `MicrosoftSecurityExposureManagement` and **RecordType** `500`.

| Operation | Description | Logged when |
|---|---|---|
| `ConnectedFoundryResource` | A user connected or updated an Microsoft Foundry resource, enabling the tenant to run agentic model scans. | A Foundry credential is created or updated. Emitted on both success and failure so rejected attempts are auditable. |
| `DisconnectedFoundryResource` | A user deleted a Foundry credential. | A Foundry credential delete is attempted. Emitted on both success and failure paths, including no-op deletes. Records the action, not the prior state. |
| `StartedCodeScan` | A scan submission was accepted. | S2S SubmitScan accepts a scan (fresh or idempotent replay). CDT-only — silently skipped on non-CDT calls. |
| `UploadedScanResults` | Scan results entered the system boundary (SARIF blob accepted or AI-scan results posted). | A SARIF blob or AI-scan result payload is accepted. `ContainsCodeSnippet` is `true` whenever the uploaded payload carries source code. |
| `ViewedScanResults` | A read-side endpoint returned scan or finding data to a caller. | Any endpoint that returns scan or finding data responds successfully. `ContainsCodeSnippet` is `true` for findings, findings-by-scan, findings-with-PR, and S2S get-results calls; `false` for aggregate and list-only views (counts, top-N, scan rows without findings). |

## Audit record schema

### Base fields

The following fields are present in every audit record. They are populated by the audit service and can't be customized.

| Field | Type | Description |
|---|---|---|
| **TenantId** | `string` | Microsoft Entra tenant ID. |
| **UpnField** | `string` | UPN of the user who performed the action. |
| **RequestorName** | `string` | Display name of the requestor. |
| **RequestorId** | `string` | Unique identifier of the requestor. |
| **RequestorType** | `string` | Type of requestor, for example `User` or `Service`. |
| **OriginIp** | `string` | IP address from which the action was performed. |
| **RecordType** | `int` | Always `500` for agentic code security. |
| **Workload** | `string` | Always `MicrosoftSecurityExposureManagement`. |
| **Operation** | `string` | The operation name. See [Audited operations](#audited-operations). |

### Operation data fields

The following four fields carry the operation-specific data. Their values vary by operation as described in the table below.

| Field | Type | Description |
|---|---|---|
| **ScanId** | `string` | Unique identifier of the scan associated with the action. `null` when no specific scan is associated. |
| **TargetIdentifier** | `string` | The resource targeted by the action. Format varies by operation — see [Per-operation field values](#per-operation-field-values). `null` when not applicable. |
| **InitiatedFrom** | `string` | Entry point used: `Portal` or `CLI`. |
| **ContainsCodeSnippet** | `boolean` | `true` if the action involved access to or processing of source code content (for example, SARIF results with inline code regions or finding detail views). `false` otherwise. |

## Per-operation field values

| Operation | ScanId | TargetIdentifier | InitiatedFrom | ContainsCodeSnippet |
|---|---|---|---|---|
| `ConnectedFoundryResource` | `null` | The Microsoft Foundry endpoint URL, for example `https://my-foundry.openai.azure.com`. | `Portal` | `false` |
| `DisconnectedFoundryResource` | `null` | `null` | `Portal` | `false` |
| `StartedCodeScan` | Scan GUID | Repository URL and branch in `{repo}\|{branch}` format, for example `https://github.com/contoso/myrepo\|develop`. | `CLI` | `false` |
| `UploadedScanResults` (portal) | Scan GUID | `null` | `Portal` | `true` |
| `UploadedScanResults` (CLI) | `null` | Repository URL and branch in `{repo}@{branch}` format, for example `https://github.com/contoso/myrepo@main`. | `CLI` | `true` |
| `ViewedScanResults` (scan-specific) | Scan GUID | Repository URL and branch in `{repo}@{branch}` format, when all findings share a single repo and branch. Otherwise `null`. | `Portal` or `CLI` | `true` |
| `ViewedScanResults` (summary views) | `null` | `null` | `Portal` | `false` |

> [!NOTE]
> **ContainsCodeSnippet** is `true` for all `ViewedScanResults` events that return individual findings, and for all `UploadedScanResults` events, because SARIF results typically include inline code regions. Use this field to identify audit records where source code content was accessed.
